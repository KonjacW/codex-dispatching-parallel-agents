# 调度与返回契约

派发任何 Agent 前，先确定任务类型、基线、范围和验收。实现与整合任务产出可审计变更集；调查与审查任务产出证据报告。

## 最小输入

| 类型 | 必须提供 |
|---|---|
| 调查 | 问题、只读范围、证据要求、停止条件 |
| 实现 | 共同基线、文件/逻辑区域、目标行为、不变量、共享符号、验证命令 |
| 审查 | 待审对象、比较基线、finding 判定标准、复现要求 |
| 整合 | 共同基线、全部原始 patch、声明范围、验证命令、冲突报告 |

## 最小返回

可写任务必须返回：

```text
基线：commit / snapshot / version
目标文件：路径及逻辑区域
意图：要改变的行为和保持的不变量
共享符号：本变更集新增或修改的顶层符号（函数、类、常量、配置键、环境变量、路由、迁移号）
变更集：可应用的 unified diff、patch 或等价结构化变更
验证：实际执行的命令及结果；声明的不变量没有可执行测试时写明"未覆盖"
风险：假设、外部依赖、未解决问题、与他人重叠的符号或契约
合并建议：可自动合并 / 需要语义审查 / 不可合并
```

`合并建议` 是写任务的子 Agent 给出的建议，不是协调器判定的状态。映射：`可自动合并` 仍须走 `integrated` 与语义审查，不因此跳过 `validated` 的前置；`需要语义审查` → `needs-review`；`不可合并` → `conflicted`。建议与协调器实际查到的证据不一致时以证据为准，协调器可以覆盖建议，并在留痕里写明理由。

调查任务没有 patch 时，必须明确写出“只读，无文件变更”，并返回证据位置。缺少基线、声明范围、可重放变更集或验证证据时，结果标记 `blocked`，不得进入集成。

## 派发模板

```text
范围：处理 <文件/逻辑区域>，允许与其他任务重叠
基线：使用协调器提供的 <commit/snapshot/version>
目标：产出独立变更集，不直接覆盖共享最终工作区
约束：只修改声明范围；不得提交、推送或执行外部写入
验收：返回 patch、影响文件、测试命令、实际结果和未决冲突
返回：变更集 + 共享符号与不变量 + 风险 + 合并建议
```

只提供当前分支需要的上下文，不复制完整项目背景。默认禁止提交、推送和外部写入；用户对总体任务的授权不会自动扩大子任务权限。

## 同文件示例

```text
范围：处理 src/config.ts 中 parseConfig；允许 validateConfig 任务同时修改该文件
基线：commit 8f21c4a
目标：新增 parseConfig 并保持现有 Config 类型不变
约束：只返回 patch，不写共享最终工作区，不提交、不推送
验收：运行 npm test -- config.test.ts 和 npm run typecheck
返回：统一 diff、实际测试结果、接口风险和合并建议
```

该任务与其他 patch 重叠时，继续读取 `overlap-integration.md`；本文件不决定合并状态。
